# 動態圖形（Motion Graphics）與 3D

何時讀：要做字卡動畫、數字與圖表、轉場、特效層，或想放 3D 物件、模擬畫面時。

狀態標示：**畫面已驗**＝用 HyperFrames 渲染範例並逐格看過畫面（原始碼在 `examples/`）；**實測**＝做在成片上過；標「參考起點」的數字是起點，請依你的畫面調整。

## 一、先記住一件事：每一格都要由「時間」決定

影片是一格一格渲染出來的，而且可能亂序渲染。所以動畫要寫成**時間的純函數**：給定時間 t，畫面就固定。

- 不要依賴「上一格的狀態」或即時播放。
- 隨機要用**固定種子**（用索引做雜湊），不要用 `Math.random()`。
- 要模擬的東西（物理、粒子）在載入時一次算完存進陣列，渲染時照時間查表。
- 同一時間點渲染兩次，截圖雜湊要一樣（SKILL.md 檢查表第 11 條）。

## 二、動態圖形的節奏與手感（數值為參考起點；逐字模糊進場、錯開、數字滾動已在 `examples/motion-techniques/` 驗過）

| 原則 | 做法 |
|---|---|
| 快的位移 | 約 0.3～0.6 秒；一個位移就是一個 tween。快速位移加動態模糊（文字大小的元素約 6～12px，全畫面約 15～20px，只沿移動方向） |
| 進場慢、離場乾淨 | 進場用長尾巴的減速曲線，落定時間比離開長；離場是一個連續動作，不要「滑、停、再走」。離場時間比進場短 40～50% |
| 依角色選曲線 | 進場落定用 `expo.out`／`power4.out`；鏡頭移動、整片換色用 `power2.inOut`；穿越、離場加速用 `power3.in`。**全部都用同一條 `power2.out` 0.5 秒，是最容易看出「機器做的」預設** |
| 彈簧 | 阻尼比 1.0 不彈；0.7～0.85 質感好；0.4～0.6 活潑；低於 0.3 像卡通。位置與大小可以彈，**透明度與顏色不要彈** |
| 重疊 | 上一個動作做到 30～50% 時下一個開始；全部依序像機器人，全部同時又廉價 |
| 錯開（stagger） | 字母間隔約 1 格；詞間隔 60～120ms；清單項目 40～80ms |
| 卡點 | 每拍格數＝fps×60÷BPM；每一拍從索引直接算再四捨五入，**不要把四捨五入後的拍長一直累加**（128 BPM、30fps 下 32 拍會漂 2 格）。切在拍上，版面變化放在小節上 |
| 切點 | 切在位移最快的那一格，前後方向與速度一致 |
| 標題落定後 | 落定的標題完全靜止，動態移給下一個元素、鏡頭或背景世界 |
| 標題進場要變化 | 全片別每張都「淡入加上滑」。可輪流用：逐字模糊轉清楚、逐字由淺灰變深、整行由模糊變清楚、逐字母出現、字躲在主體後面、一個詞像拉霸機滾動 |
| 停留時間 | 要讀的句子約 0.5 秒加每字 0.3 秒；片尾最後一句至少 2 秒；一兩個字的章名可 0.4 秒 |
| 標題大小 | 約畫面高度 4～9%、一到兩行；安靜的字 2.5～4%，主角字可撐滿 60～90% 寬；一個強調字用強調色 |
| 節奏對比 | 蒙太奇每 0.13～0.8 秒一切；示範畫面可停 7～10 秒讓 UI 自己動；一般鏡頭平均 1.8～3 秒，鏡頭內要有動；亮點前先停 0.3～0.75 秒 |

**看起來像機器做的預設（要避開）**：用呼吸、漂浮、脈動循環假裝有動態；標題落定後還在慢慢滑或放大；每個場景用同一種方式進場；每個元素都淡入加上滑；UI 上的彈跳；點擊圈圈。

## 三、有原因的轉場（一支片用 3～5 種，每種都由畫面上的東西引起）

硬切適合用在場景內（推近）；場景之間的接縫，硬切不超過三分之一；兩個世界之間不要直接交叉淡化。

| 轉場 | 怎麼做（數字是參考起點；表中每一種都在 `examples/transitions/` 驗過畫面） |
|---|---|
| 整片換色 | 主角物件不動，整個底色約 0.4 秒換色 |
| 甩鏡 | 橫向或直向模糊 0.13～0.3 秒，新元素帶模糊進來、約 0.13 秒變清楚 |
| 從點擊處開圈 | `clip-path: circle()` 從點擊位置展開成下一個世界（約 0.15 秒） |
| 暗角切 | 硬切前，離場畫面約暗 40% 持續 3 格，讓這一刀看起來是故意的 |
| 同一舞台模糊交換 | 出：透明度到 0 並模糊約 8px；進：模糊到 0；底板不切 |

## 四、數字與圖表

- **一次一個數字**：先用前一個場景鋪墊，再讓它「有分量」（例如數字長成天際線）。數字是畫面上最大的東西；用等寬數字（`font-variant-numeric: tabular-nums`）避免滾動時抖動；滾動 1.2～1.6 秒，然後停住。數字滾動**畫面已驗**（`examples/motion-techniques/`，1.4 秒滾到 1,280 後停住）。
- 只用來源裡的真資料，全片同一種進位方式，畫面上加一行小小的來源。一個資料模組驅動全片所有數字。
- **圖表要當成「畫面」做**：依閱讀順序建構（座標框→參考線→資料畫出來→只在關鍵點加一個註解）；註解直接標在點上，不放圖例；只強調一條線，其他變灰；一張圖只說一件事，說在標題裡。
- 同一個物件可以跨段落延續（長條變成下一場景的地面、折線變成鏡頭跟著走的路）。
- 避免：一整排 KPI 卡、儀表板、圓餅圖、所有數字同時滾動、沒有來源的數字。
- 圖表函式庫的動畫要由時間軸驅動（在 GSAP tween 的 `onUpdate` 裡更新），不要用函式庫自己的過場。

## 五、動畫引擎怎麼選

| 引擎 | 適合 | 備註 |
|---|---|---|
| GSAP | 大多數字卡、位移、時間軸 | **實測**、畫面已驗；要點見 SKILL.md「實作踩坑」。把動畫放在絕對秒數（`tl.to(el, {...}, 2.4)`）；起始狀態寫在 tween 裡（`fromTo`）；版面只在建立 tween 前量一次 |
| Three.js | 3D 畫面 | 畫面已驗（`examples/three-dive/`）；見下一節 |

文字要塞進固定寬度時，先量文字再決定字級，不要寫死。

## 六、3D（Three.js）：什麼時候值得放

**只在 3D 本身是重點時才用**：一個物件或場景是這支片的高潮、產品展示、用模擬來解釋一件事。

**已驗證的做法**（範例 `examples/three-dive/`：一個結點物件，鏡頭由遠推近，2.5 秒、4.9 秒、5.8 秒抽格畫面正常；同一時間點渲染兩次，截圖 md5 相同）：
- **每一格由時間 t 畫出來**：在 `hf-seek` 事件裡呼叫 `renderAt(t)`，物件旋轉與鏡頭位置都只由 t 算，不依賴上一格；不要用 `requestAnimationFrame` 當時鐘。
- 渲染器要開 `preserveDrawingBuffer: true`，截圖與逐格渲染才拿得到畫面。
- 要另外註冊一個空的 GSAP 時間軸（`window.__timelines["main"]`），composition 才算合法（lint 會檢查）。
- **穿越，不是繞圈**：鏡頭由遠推近鑽進物件，比繞著轉更有動勢。
- **打光**：暖色主光加冷色輪廓光加低亮度環境光，範例畫面中高光與暗部分離清楚。

**設計原則**（取捨建議，不是功能保證）：
- 一個主角物件勝過一群。
- 鏡頭外加說明：切面圖、每章一句字卡、標籤放真實數字，模擬才會變成解釋，不只是好看。
- 產品 UI 不要傾斜成 3D，只有生成的內容才傾斜。
- 3D 場景較重，最重的那一格先量渲染時間，再決定畫質。

## 七、做動態圖形前先查現成的

用素材庫的搜尋功能，用英文描述要的效果（例如 `npx hyperframes catalog --query "kinetic type" --json`、`--tag transition`、`--tag camera`），已有的元件先用，沒有才手刻，並記下缺口。
