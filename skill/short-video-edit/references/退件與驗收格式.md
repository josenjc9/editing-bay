# 退件與驗收格式

何時讀：階段四大片檢查表自查時、使用者退件要整理成修正清單時。

## 原則：使用者批准仍是唯一的 pass。這裡只是讓「自查」和「修正清單」有固定格式。
三層判定，別混：`technical`（腳本能算）／`semantic`（要看畫面、聽聲音）／`audience`（要真人，agent 不能代替）。沒觀察證據不寫 pass，寫 `unverified`。

## Severity
- `blocking`：播不動、素材缺、主體身份重大錯、與使用者指定內容重大不符、外洩敏感資訊 → 不得交。
- `major`：劇情混淆、跨鏡主體或動作顯著錯、字幕擋核心、聲音蓋過人聲、節奏嚴重斷裂 → 修完或使用者明說接受才交。
- `minor`：不影響理解 → 列在交付說明，照原定交。
- `suggestion`：偏好，不自動退件。

## 每個問題一行（寫進交付說明）
`ISS-編號｜severity｜維度（連續性／節奏／聲音／字幕／畫質）｜鏡頭或時間碼｜實際 vs 預期｜證據（圖路徑）｜owner｜最小修法｜再測方法`
沒有圖路徑的意見標 `hypothesis`，不當退件依據。

## 寫審查意見的三條規則（2026-11-11 讀 OpenMontage 的審查規範後，用自己的話改寫）
- **準確**：每條意見要指到具體的鏡頭、時間碼、檔案欄位或畫面；指不出來就是猜，不寫成問題。
- **完整**：找到一個問題，就把同一類問題在整支片裡再掃一輪，不要只修被抓到的那一處。
- **建設性**：`blocking`、`major` 一定附最小修法；附不出修法的，降成 `investigation`（待調查，列給下一輪，不擋交付）。

## 修正規則
- 順序：改切點 → 換序 → 變速 → 調字幕混音 → 重合成 → 局部重渲 → 整支（最後手段）。一個 minor 不准觸發整支重渲。
- 同一問題自己修最多 2 輪，仍不過就停、把兩輪結果給使用者裁決。
- 修完只重驗：受影響鏡頭、相鄰切點、全片可播放（`tools/qa_video.py`），避免修一段壞一段。
- 保留上一版可播放正式版以便回退；中間版放 `.work/`，不覆寫已核准成品。

## 值得記的指標（有紀錄才填，不估）
使用者退件輪次、第一次自查抓到的 blocking 數、重生鏡頭數、人工介入次數。寫進覆盤。
